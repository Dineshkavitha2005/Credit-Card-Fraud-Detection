Security Engineering

Enterprise Security & Encryption Standards

Financial surveillance platforms must meet rigorous data protection standards. Sentinel is architected from the ground up with defense-in-depth principles to safeguard cardholder information and prevent unauthorized system access.

1. Cryptographic Cardholder Protection (AES-128-CBC)

Storing credit card numbers in plaintext is an unacceptable vulnerability. Sentinel guarantees that full Primary Account Numbers (PANs) are never written to disk unencrypted:

  • Fernet Symmetric Encryption: Sensitive card numbers are encrypted using 128-bit AES in CBC mode with PKCS7 padding and authenticated via HMAC-SHA256.
  • Externalized Keys: The master encryption key (CARD_ENCRYPTION_KEY) is loaded exclusively via secure container environment variables and is never committed to code repositories or database records.
  • Display Masking: User interfaces and API outputs strictly expose masked tokens (e.g. **** **** **** 8891). Only authorized administrative actions can trigger cryptographically verified decryption.

2. Modern Identity & Authentication (Google OAuth 2.0 + PKCE)

Sentinel incorporates enterprise-grade identity controls supporting both local credential access and Google OpenID Connect:

  • PKCE Protection: The Google OAuth 2.0 flow implements Proof Key for Code Exchange (RFC 7636) with SHA-256 challenges, eliminating authorization code interception vulnerabilities.
  • Cryptographic State Nonces: Every login attempt includes high-entropy cryptographic state parameters validated server-side to prevent cross-site request forgery (CSRF) and replay attacks.
  • Credential Hashing: Local passwords are processed using PBKDF2-HMAC-SHA256 with distinct random salt strings per user and high work factors.
  • Session Governance: Active user sessions can be inspected and remotely invalidated at any time from the security settings console.

3. Immutable PostgreSQL Audit Trails

Every security-relevant operation creates an audit log entry in the PostgreSQL database:

  • Tracks authentication attempts, card block/unblock actions, rule edits, and report generation.
  • Logs capture timestamp, user ID, client IP address (resolved via trusted proxy headers), user agent, event status, and contextual metadata.
  • System administrators cannot alter or delete audit history, providing compliance-ready evidence for external security reviews.

4. Role-Based Access Control (RBAC)

System privileges are partitioned strictly by authorization tiers:

  • Analyst Role: Authorized to monitor live transaction streams, review flagged transactions, and generate analytical reports.
  • Administrator Role: Exclusive privileges to configure heuristic fraud rules, manage user accounts, inspect global audit trails, and oversee system configuration.

5. Network & HTTP Transport Hardening

Production deployments enforce strict transport security policies:

  • Mandatory HTTPS via Nginx with automated HTTP-to-HTTPS 301 redirection.
  • HTTP Strict Transport Security (HSTS) with max-age=31536000; includeSubDomains.
  • HTTP response security headers: X-Content-Type-Options: nosniff, X-Frame-Options: SAMEORIGIN, Referrer-Policy: strict-origin-when-cross-origin, and restrictive Content Security Policy (CSP).
  • Automated X-Robots-Tag: noindex, nofollow headers across all private dashboards and APIs to prevent indexing by search engine crawlers.
