Frequently Asked Questions

Everything you need to know about Sentinel's machine learning architecture, transaction processing latency, security posture, and production deployment options.

How does Sentinel score transactions without delaying checkout?
Sentinel features a pre-compiled, optimized machine learning pipeline using scikit-learn standard scalers and calibrated models. End-to-end inference executes in under 10 milliseconds, allowing inline risk scoring well within standard payment gateway timeout thresholds.
How does Sentinel ensure cardholder data security and PCI-DSS compliance?
Sentinel never stores plaintext Primary Account Numbers (PANs). All card numbers are encrypted using AES-128-CBC with Fernet keys stored in environment variables, and public interfaces strictly render masked values such as **** **** **** 1234.
Can compliance teams adjust fraud rules without redeploying code?
Yes. Sentinel includes a dynamic heuristic rule engine. Administrators can adjust amount thresholds, transaction velocity limits, nocturnal risk multipliers, and card velocity checks dynamically through the web console or database.
How does Google OAuth 2.0 authentication work in Sentinel?
Sentinel implements the Google OAuth 2.0 authorization code flow reinforced with Proof Key for Code Exchange (PKCE) and cryptographic session states, ensuring robust protection against authorization code interception and CSRF attacks.
What database systems are supported in production?
Production deployments strictly require PostgreSQL with connection pooling (pool_pre_ping, max_overflow, pool_recycle). SQLite is strictly restricted to local development and testing environments.
How does Sentinel differentiate genuine high-value purchases from fraud?
Rather than relying solely on dollar amounts, Sentinel's model evaluates 28 principal component features alongside contextual signals like merchant category, IP consistency, device historical patterns, and time-of-day baselines, drastically reducing false positive declines for legitimate VIP customers.
