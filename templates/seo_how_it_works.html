Pipeline Architecture

How Sentinel Inspects Every Transaction

Sentinel combines statistical feature normalization, high-dimensional machine learning inference, and deterministic rule engines into an asynchronous evaluation pipeline designed to minimize false positives while preventing unauthorized settlements.

1. Transaction Ingestion & Payload Sanitization

Payment transactions enter Sentinel through structured REST APIs or automated simulator webhooks. The request undergoes immediate schema validation:

  • Non-negative numeric amount validation and currency normalization.
  • Card number structural validation and sanitization.
  • Client IP extraction with forward proxy header resolution (X-Forwarded-For).
  • Geographical lookup to map origin city, country, and ASN details.

2. High-Dimensional Feature Engineering

Machine learning models require consistent numerical scaling. Sentinel passes raw inputs through a pre-trained preprocessing pipeline:

  • PCA Transformation: 28 principal component features (V1 through V28) capturing transaction dimensionality, user behavior history, and merchant clustering.
  • Robust Scaling: Transaction amount and time deltas are scaled using trained scikit-learn standard scalers, preventing high-dollar outliers from skewing model weights.
  • Temporal Features: Cyclical hour and day encodings detect nocturnal surges and off-hour transaction anomalies.

3. Supervised Model Inference

The normalized feature vector is supplied to the primary classification engine—an optimized ensemble model trained on over 284,000 transaction records. The model calculates a calibrated posterior fraud probability:

P(Fraud | X) = Model.predict_proba(X)[1]
Verdict = "Fraudulent" if P(Fraud | X) >= 0.50 else "Genuine"

4. Deterministic Heuristic Fusion

Machine learning probabilities are merged with real-time heuristic evaluations. If a transaction is statistically ambiguous (e.g. 0.35 risk score) but triggers multiple heuristic rules (such as a 3rd rapid transaction within 60 seconds from an unrecognized international IP), Sentinel elevates the risk level to High Risk or Manual Review.

5. Automated Enforcement & Audit Logging

Depending on the computed risk tier, Sentinel executes automated actions:

  • Low Risk (< 0.30): Approved automatically with minimal latency.
  • Medium Risk (0.30 – 0.69): Flagged for supervisory review in the analyst console.
  • High Risk (>= 0.70): Intercepted, transaction declined, card auto-blocked, and immediate security alert dispatched.
  • Audit Trail: Every evaluation is permanently recorded in PostgreSQL with timestamp, user agent, client IP, raw scores, and triggering rule IDs for regulatory compliance.
